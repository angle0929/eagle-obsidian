### 踩过的坑（重要）
1. Git Bash 的 `cp` 不支持 `--exclude`，备份必须改用 Python `shutil.copytree(ignore=...)`。失败那次会留下空目录，要清掉。
2. `os.makedirs(os.path.dirname(dst))` 在 dst 无父路径时（如 `06-日记`）会因 `dirname=''` 抛 `FileNotFoundError`，必须先判空。
3. 批量改写 MOC/笔记的脚本**必须幂等**：否则二次运行会把上一轮生成的标题行、导航行、目录标题当成"正文"保留，导致内容重复。做法是每次运行前先剔除自己生成的脚手架行（`# ` / `> ` / `## 目录`）。更稳妥的是"复位脚本 + 单次运行"。
4. 校验断链时不能用 `os.path.splitext` 判断扩展名——`千问3.5-plus`、`文稿及推文排版 2026.3.26` 这类文件名会被误判，产生假断链。要用已知扩展名白名单。
5. 校验时要剔除行内代码与代码块，否则教程里演示语法的 `[[笔记标题]]` 会被误报为断链。
6. 解析已有链接时若不清掉导航行，导航目标（上级索引、主页）会被收进"目录"，产生自指链接。

## 追加：Dataview / Obsidian Bases 选型咨询

用户问 Dataview 是什么、是否值得装。

**关键事实**：本库 `.obsidian/core-plugins.json` 中 `"bases": true` —— Obsidian 官方 Bases（核心插件，2025 年随 v1.12 引入）已启用，无需安装任何插件即可用数据库视图。

**给出的结论**：暂不装 Dataview，先用 Bases。理由：
- Bases 覆盖其 80%~90% 需求（按域/专题/类型筛选、分组、卡片视图、表格内直接编辑属性）
- 该库的 frontmatter 已 100% 结构化（domain/topic/type/tags/created/updated），正是 Bases 的理想数据源
- Dataview 独有能力（任务级聚合 TASK、行内字段 `key:: value`、DataviewJS、行内查询）目前用不上：日记里没有带 due 日期的 markdown 任务
- 触发升级的条件：需要跨笔记聚合待办任务 / 需要 JS 自定义输出 / 需要把查询结果写回 Markdown

**产出**：新建 `00-笔记总表.base`（4 个视图：全部笔记按域分组、按专题分组、索引卡片、需要复习）。
Bases 的 `.base` 文件为 YAML，schema：filters / formulas / properties / summaries / views；
无 `FROM`（默认全库），筛选用 `file.hasTag()`、`file.inFolder()`、比较表达式；视图类型 table/cards/list/map。
