## 零、方案变更说明

### 为什么Chroma必须被替换？

| 问题     | Chroma（本地）         | Pinecone / Qdrant Cloud |
| ------ | ------------------ | ----------------------- |
| 多用户访问  | ❌ 存在个人电脑，其他人无法访问   | ✅ 云端，全院师生共用             |
| 数据一致性  | ❌ 每人一份拷贝，老师更新学生看不到 | ✅ 单一数据源，实时同步            |
| 持久化与备份 | ⚠️ 依赖个人电脑不关机       | ✅ 云端自动备份                |
| 并发性能   | ❌ 单机瓶颈             | ✅ 弹性伸缩                  |
| 部署形态   | 个人工具               | 医院级App                  |

**结论：必须从Chroma升级到云端向量数据库。推荐Qdrant Cloud（开源、有免费层、LangChain原生支持）。**

### 2.3 为什么JSON仍然是编辑入口？

在医院场景中，带教老师需要能随时修改知识库内容（更新操作规范、补充新病例）。JSON文件存放在Git仓库中：

- **老师**：编辑JSON → Git push → 触发自动同步脚本 → 更新PostgreSQL + 重新向量化 → 更新Qdrant
- **学生**：只能读取，不能编辑知识库
- **好处**：版本可追溯、多人协作有冲突解决机制、误操作可回滚

## 三、LangChain的作用详解

### 3.1 LangChain在这个项目中具体做什么

```
┌──────────────────────────────────────────────────┐
│              LangChain 在项目中的六大职责          │
│                                                   │
│  ① 文档加载与分块                                 │
│     JSON文本 → LangChain Document对象 → 语义分块   │
│                                                   │
│  ② Embedding生成与管理                            │
│     调用BGE-M3 → 向量化 → 批量写入Qdrant          │
│     LangChain的Qdrant向量库封装隐藏了API细节       │
│                                                   │
│  ③ 检索链 (Retrieval Chain)                       │
│     用户问题 → 向量化 → Qdrant相似搜索             │
│     → 返回Top-K + 元数据                          │
│                                                   │
│  ④ 问答链 (QA Chain)                              │
│     检索结果 + 用户问题 → 拼成Prompt               │
│     → DeepSeek API → 解析答案                     │
│                                                   │
│  ⑤ 路由链 (Router Chain)                          │
│     判断：纯文字? → DeepSeek直接回答               │
│           带图片? → Qwen-VL先理解 → DeepSeek整合   │
│           带视频? → 视频分析流水线                  │
│                                                   │
│  ⑥ 记忆管理 (Memory)                              │
│     多轮对话上下文保持，"刚才说的那个步骤…"        │
│     LangChain的ConversationBufferMemory处理        │
└──────────────────────────────────────────────────┘
```

### 3.2 核心代码骨架（LangChain天然简洁）

```python
from langchain.embeddings import HuggingFaceBgeEmbeddings
from langchain.vectorstores import Qdrant
from langchain.chains import RetrievalQA
from langchain.llms import DeepSeek  # 假设适配器
from qdrant_client import QdrantClient
from qdrant_client.http import models as qmodels

# --- 初始化 ---
embeddings = HuggingFaceBgeEmbeddings(model_name="BAAI/bge-m3")
qdrant_client = QdrantClient(url="https://your-cluster.qdrant.cloud", api_key="xxx")

vectorstore = Qdrant(
    client=qdrant_client,
    collection_name="medical_knowledge",
    embeddings=embeddings
)

# --- 检索增强生成 ---
qa_chain = RetrievalQA.from_chain_type(
    llm=DeepSeek(model="deepseek-v3"),
    retriever=vectorstore.as_retriever(search_kwargs={"k": 5}),
    return_source_documents=True   # 返回源文档 → 可提取image_path
)

# --- 查询 ---
result = qa_chain("持针器应该握在哪里？")
# result["answer"]  → 文字回答
# result["source_documents"] → 包含payload中的image_path和annotations
```

关键点：`return_source_documents=True`让LangChain在返回答案的同时，把命中的原始文档元数据（`image_path`、`annotations`）也返回，前端据此渲染图片和标注。

## 四、图片处理全链路（核心创新点）

### 4.1 知识库图片的入库流程

```
带教老师准备图片
        │
        ▼
1. 图片文件上传到OSS → 得到URL
   "https://oss.xxx.com/images/suture_grip.jpg"
        │
        ▼
2. 在JSON中手写：
   - image_path: OSS的URL
   - image_description: "持针器标准握持，食指抵关节，握后1/3"
   - annotations: [{x, y, label, type, color}, ...]
        │
        ▼
3. 同步脚本执行：
   - image_description 文本向量化 → Qdrant
   - 向量对应的payload存储：
     {
       "procedure_id": "suture_needle_holder_grip",
       "step_number": 1,
       "image_url": "https://oss.xxx.com/images/suture_grip.jpg",
       "annotations": [...],
       "source_text": "持针器标准握持..."
     }
        │
        ▼
4. 学生检索时：
   问题 → 向量 → Qdrant命中 → 返回payload
   → 前端拿到 image_url + annotations → 渲染带标注的图片
```

### 4.2 回答中附带标准图片的完整流程

```
学生提问："持针器握在哪里算错误？"
        │
        ▼
LangChain RetrievalQA Chain:
  ① 问题向量化
  ② Qdrant检索 → Top-5 结果
  ③ 每个结果包含payload：
     - 原文片段
     - image_url
     - annotations
        │
        ▼
LangChain将Top-5原文拼接为Context → 发给DeepSeek
        │
        ▼
DeepSeek生成文字回答 +
系统从Top-1结果的payload中提取 image_url + annotations
        │
        ▼
FastAPI响应JSON：
{
  "answer": "正确的持针器握持方式是：握住后1/3处，食指抵住关节... 常见错误是握得太靠前。",
  "related_images": [
    {
      "url": "https://oss.xxx.com/images/suture_grip.jpg",
      "caption": "持针器标准握持示意",
      "annotations": [
        {"x":320,"y":180,"radius":30,"label":"食指应抵此处","type":"circle","color":"#FF0000"}
      ]
    }
  ]
}
        │
        ▼
前端渲染：
  - 显示文字回答
  - 加载图片
  - 用Canvas/SVG在图片上绘制红圈和标注文字
```

**原理总结**：图片不参与向量检索，但图片的路径和标注坐标作为检索结果的"附属品"一起返回。图片本身通过OSS URL直接加载。

### 4.3 在学生操作截图上动态标注（进阶功能）

这是您特别提出的需求——在学生自己的操作视频截图上画圈指出错误。

```
学生上传操作视频 → 抽帧 → 某帧图片
        │
        ▼
1. 图片发送给 Qwen-VL-Max，使用特殊提示词：

   "分析这张手术模拟操作图片。
   当前标准步骤是：{从JSON加载的正确步骤描述}
   请完成：
   ① 描述操作者当前动作
   ② 判断是否有错误
   ③ 如果有错误，给出错误区域的bounding box坐标
      (格式: {x, y, width, height}，图片尺寸1280×720)
   ④ 给出纠正建议"
        │
        ▼
2. Qwen-VL返回JSON：
   {
     "action_desc": "右手持持针器，正在进针",
     "has_error": true,
     "error_desc": "持针器握持位置过于靠前",

        │
        ▼
3. 后端Pillow处理：

   img.save("annotated_frame_001.jpg")
        │
        ▼
4. 同时从知识库中取出标准操作图片（带预存标注）作为对比
        │
        ▼
5. 返回给学生：
   {
     "feedback": "持针器握持位置有误...",
     "error_frame": "https://oss.xxx.com/annotated_frames/xxx.jpg",

       "url": "https://oss.xxx.com/images/suture_grip.jpg",

     }
   }
        │
        ▼
前端展示：左侧=学生的错误截图（红框标注），右侧=标准操作示意图（绿圈标注）
```

### 4.4 Qwen-VL输出Bounding Box的可行性

截至当前的Qwen-VL模型版本，已支持输出目标位置描述（如"图片左侧偏上位置"），但**精确像素级bbox输出**需要特定Prompt调优。具体做法：

- 在Prompt中明确要求输出bbox格式
- 可以使用Grounding DINO（开源目标检测模型）辅助Qwen-VL定位
- **备选方案**：如果Qwen-VL不能稳定输出精确坐标，可以让学生**手动点击错误位置**（在平板上点一下），系统只需在那一点周围画圈即可——这反而更准确，且实现极简单

## 五、视频分析全链路

### 5.1 整体流程

```
学生上传换药操作视频（3分钟，1280×720，30fps）
        │
        ▼
┌──────────────────────────────────────────────┐
│  Step 1: FFmpeg智能抽帧                       │
│  场景变化检测 → 关键帧提取（约40-60张）         │
│  而非均匀3秒抽帧（更精准捕获动作转换瞬间）       │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│  Step 2: 批量Qwen-VL帧描述                    │
│  并发调用（asyncio + 限流）→ 每帧生成JSON：    │
│  {action, instrument, target, confidence}    │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│  Step 3: 步骤序列归并                         │
│  连续相似帧合并 → 形成步骤序列                 │
│  [{step:1, action:"揭除旧敷料"},              │
│   {step:2, action:"观察伤口"}, ...]           │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│  Step 4: 与JSON标准步骤比对                   │
│  - 顺序检查（是否跳步）                        │
│  - 动作匹配（当前步骤动作是否与标准一致）        │
│  - 器具检查（是否使用正确器具）                 │
│  - 时长检查（消毒揉搓是否≥15秒）                │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│  Step 5: 错误帧定位+标注                      │
│  发现错误的帧 → Qwen-VL获取bbox               │
│  → Pillow画红框标注 → 返回标注图              │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│  Step 6: DeepSeek生成综合评语                  │
│  汇总所有错误+正确步骤 → 生成自然语言反馈报告   │
└──────────────────────────────────────────────┘
```

### 5.2 关键技术细节

**FFmpeg智能抽帧命令**（检测场景变化超过30%时抽帧）：
```bash
ffmpeg -i student_video.mp4 \
  -vf "select='gt(scene,0.3)',scale=1280:720" \
  -vsync vfr frames/frame_%04d.jpg
```

**批量帧分析的异步并发控制**：
```python
import asyncio
from langchain.callbacks import get_openai_callback

async def analyze_frame(frame_path, standard_step_context):
    # 调用Qwen-VL API
    ...

# 控制并发数，避免API限流
semaphore = asyncio.Semaphore(5)

async def bounded_analyze(frame):
    async with semaphore:
        return await analyze_frame(frame, context)

results = await asyncio.gather(*[bounded_analyze(f) for f in frames])
```

## 六、模型路由设计

### 6.1 路由决策树

```
                      用户输入
                         │
                 ┌───────▼────────┐
                 │  轻量意图分类   │
                 │  (关键词+规则)  │
                 └───┬───┬───┬───┘
                     │   │   │
        ┌────────────┘   │   └──────────────┐
        ▼                ▼                  ▼
   纯文字提问       附带图片提问        视频上传
        │                │                  │
        ▼                ▼                  ▼
  直接走RAG链      图片→Qwen-VL        进入视频
  DeepSeek回答     →转文字描述         分析流水线
                   →再走RAG链
                   →DeepSeek整合
```

### 6.2 模型矩阵

| 模型 | 调用场景 | 调用频率 | 延迟要求 |
|------|----------|----------|----------|
| **DeepSeek V3** | 所有最终回答生成、推理整合 | 每次请求 | <3s |
| **Qwen-VL-Max** | 图片理解、视频帧描述、错误bbox定位 | 图片提问/视频分析时 | <1s/图 |
| **BGE-M3** | 知识库文本向量化、用户问题向量化 | 每次搜索 | <200ms |
| **讯飞ASR**（可选） | 视频中语音转文字，辅助步骤判断 | 视频分析时 | 离线即可 |

| 角色 | 权限 |
|------|------|
| **实习生** | 提问（文字+图片+视频）、查看历史记录、查看个人学习报告 |
| **带教老师** | 以上全部 + 管理知识库JSON + 查看所带学生的所有记录 + 手动标注典型案例 |
| **管理员** | 以上全部 + 用户管理 + 系统配置 |

### 7.2 数据库表设计（PostgreSQL核心表）

```
users:
  id, username, password_hash, role(enum:student/teacher/admin),
  real_name, department, created_at

query_history:
  id, user_id, query_type(enum:text/image/video),
  question_text, answer_text, related_images(jsonb),
  created_at

video_analyses:
  id, user_id, procedure_id, video_url,
  detected_steps(jsonb), errors(jsonb),
  annotated_frames(jsonb[]), overall_score,
  teacher_review(text), created_at

knowledge_revisions:
  id, editor_id, old_json(text), new_json(text),
  diff_summary, created_at
```

**对比**：计算机专业本科生一门4学分课程的标准学时为160小时（含上课+作业+项目）。您的总投入约等于**6门课程**的工作量，分散在3年完成，完全合理。

### 10.2 核心降难度策略

| 难点 | 降难度方法 |
|------|-----------|

## 十二、最终总结

### 方案核心特征回顾

```
┌─────────────────────────────────────────────────────────┐
│                    最终方案六要素                        │
│                                                         │
│  ① 知识库：JSON手写维护 → PostgreSQL → Qdrant Cloud    │
│     图片不向量化，靠人手描述检索，路径+标注坐标存在      │
│     payload中随检索结果一同返回                          │
│                                                         │
│  ② 框架：LangChain 编排全部RAG流程                      │
│     - Document加载 → Embedding → Qdrant检索             │
│     - RetrievalQA Chain → DeepSeek生成                  │
│     - Router Chain → 模型分发                           │
│                                                         │
│  ③ 图片回答：检索命中 → payload提取image_url+           │
│     annotations → 前端Canvas绘制标注 → 学生看到         │
│     带红圈/箭头的操作示意图                              │
│                                                         │
│  ④ 学生截图标注：Qwen-VL输出bbox → Pillow后端           │
│     绘制矩形+文字 → 返回标注图 + 标准图对比              │
│                                                         │
│  ⑤ 视频分析：FFmpeg智能抽帧 → Qwen-VL批量描述           │
│     → 步骤归并 → JSON标准比对 → 错误帧标注               │
│                                                         │
│  ⑥ 多用户：JWT认证 + PostgreSQL用户表 + 角色权限        │
│     全院师生使用，老师可管理知识库                        │
└─────────────────────────────────────────────────────────┘
```

### 时间承诺

**大一入学 → 大三结束 = 约2.5年，每周课余投入约10小时，一名精力充沛的医学生完全可以在大四之前完成。**

这不是一个"降低标准让学生勉强完成"的方案，而是一个**充分利用了2026年AI工具链、让医学生以产品经理+领域专家的身份主导、AI承担编码工作**的现实路径。您的医学知识是这个项目最稀缺的资源，技术问题DeepSeek帮您解决。
