## 一、项目背景与需求

**目标**：构建一个AI Agent/App，辅助医学实习生进行临床技能学习，具备两大功能：

| 需求编号 | 场景描述 | 输入 | 期望输出 |
|----------|----------|------|----------|
| **需求1️⃣** | 理论知识问答 | 学生以文字提问（可附带图片） | 结合知识库，回复准确的医学知识、操作指南、器具说明、顺序等 |
| **需求2️⃣** | 模拟操作指导 | 学生在练习室中面对模型操作，录制视频后上传 | 分析操作步骤，识别错误，给出改进意见 |

**实施主体**：医学大一本科生（无AI专业背景）。
**约束**：全部使用国产大模型API，核心推理引擎选定DeepSeek系列（纯文本推理最强）；知识库需支持文字、图片、视频、DICOM影像等多模态资料。

---

## 二、方案核心思路

1. **知识库由医学生自己按结构化JSON维护**，而不是直接将原始教材文档丢进黑箱RAG系统。
2. **借助极轻量级向量数据库（Chroma）**，自动将JSON中的文本描述向量化，实现语义检索。
3. **推理时采用模型路由**：文字逻辑推理全部交给DeepSeek（纯文本最强），视觉理解（图片、视频帧、DICOM关键切片）调用国产多模态模型（如Qwen-VL-Max），再转换成文字送DeepSeek二次处理。
4. **学生操作视频的分析**采用“抽帧→多模态描述→与标准步骤比对”的流水线，而非实时动作识别，极大降低实现难度。

**最终交付形态**：一个支持文字问答和视频提交分析的Web/小程序应用，全部代码量控制在200行Python左右，全程可由AI辅助编写。

## 三、知识库设计（核心构建）

### 3.1 存储形式

所有医学知识以**单个JSON文件**（`knowledge_base.json`）存储，由医学生手工编写和维护。图片、视频、DICOM原文件独立存放在文件夹中，JSON内仅记录**文件路径**和**手写的文字描述**。

### 3.2 JSON结构示例

```json
{
  "procedures": [
    {
      "id": "hand_washing_7steps",
      "title": "七步洗手法",
      "category": "基础护理",
      "supplies": ["洗手液", "流动水"],
      "steps": [
        {
          "step_number": 1,
          "action": "掌心相对，手指并拢，相互揉搓",
          "duration_seconds": 15,
          "key_points": ["手指并拢", "全面接触"],
          "common_errors": ["手指未并拢，留有空隙"],
          "image_reference": "images/handwash_step1.jpg",
          "image_description": "双手掌心相对，十指并拢，进行旋转揉搓"
        }
        // ... 其余步骤
      ],
      "text_description": "七步洗手法是预防院内感染的基础操作……",
      "demo_video_path": "videos/handwash_demo.mp4",
      "demo_video_description": "展示完整七步洗手流程，总时长2分钟，重点突出揉搓手法和持续时间"
    }
  ]
}
```

### 3.3 为什么用JSON而不用传统RAG？

- **结构化优势**：医学操作流程是高度结构化的（步骤顺序、器具、常见错误），JSON天然适合表达“步骤链”关系，方便后续做**确定性步骤比对**，而传统RAG会把步骤打散，丢失顺序依赖。
- **可维护性**：医学生直接编辑文本，可用Git做版本管理，无需学习复杂框架。
- **节约资源**：无需部署RAGFlow等重型服务，只需一个JSON文件 + Chroma索引。

### 3.4 向量化与语义检索

- 使用轻量开源嵌入模型（如`BGE-small-zh`），将JSON中所有`text_description`、`action`、`image_description`字段拼接后转换为向量，存入Chroma。
- **检索流程**：学生输入问题 → 问题向量化 → 在Chroma中搜索最相似的Top-K段文字 → 原文原文返回，拼入提示词给大模型。
- Chroma在本地运行，零配置，索引自动生成，医学生只需执行一次初始化脚本。

## 四、图片与视频的处理策略

### 4.1 图片处理

- **知识库图片**：原图保存在`images/`目录，JSON中存`image_path`和`image_description`。展示时直接读取图片文件；检索时依赖`image_description`的文本向量。
- **学生提问时上传的图片**（如解剖图、操作场景）：**不入知识库**，而是实时发送给多模态模型（Qwen-VL-Max），将其描述为文字，再作为上下文交给DeepSeek推理。

### 4.2 视频处理

- **教学视频**：原文件存放在`videos/`，JSON中存`demo_video_description`，用于检索和学生点播。若需要更精细定位，可手动在JSON中定义`keyframes`（时间戳+动作描述+帧截图）。
- **学生操作视频**（需求2️⃣的核心）：
  1. 视频上传后，用FFmpeg自动每隔3秒截取一帧。
  2. 每一帧调用多模态模型Qwen-VL-Max，提取动作描述（如“右手持镊子夹起碘伏棉球”）。
  3. 得到一连串文字描述，形成“操作序列”。
  4. 与JSON中预定义的标准操作步骤进行**逐条比对**，检测：
     - 步骤顺序是否一致
     - 使用的器具是否正确
     - 动作关键词是否符合规范
  5. 若偏差超过阈值，从JSON的`common_errors`中匹配最可能的错误，生成指导文本。

**视频本身从不进行向量化**，只作为多模态模型的输入；知识库中也不存学生视频，分析后可删除。

## 五、模型选择与智能路由

### 5.1 模型矩阵

| 角色 | 选用模型 | 调用的时机 |
|------|----------|-----------|
| 文字推理主脑 | **DeepSeek-V3**（API） | 所有需要深度医学推理、综合多源信息生成最终回答的场景 |
| 图片/视频帧理解 | **Qwen-VL-Max** | 学生上传图片/视频帧需要视觉理解时 |
| DICOM解读 | **紫东太初医学版** 或 **Qwen-VL-Max** + 医学提示词 | DICOM影像需解读诊断或解剖结构时 |
| 文本嵌入 | **BGE-small-zh** | 知识库文本向量化及用户问题向量化 |
| 语音转文字（可选） | **讯飞ASR** | 若学生用口头描述代替某些操作标记 |

### 5.2 路由决策逻辑

通过**规则引擎**（几十行`if-else`）而非训练模型进行分类：
- 纯文字问题 → 直接调用DeepSeek，知识库检索结果作为上下文。
- 问题附带图片 → 图片先送Qwen-VL，返回文字描述 → 拼接问题文字一起送DeepSeek。
- 视频分析 → 先抽帧，每帧送Qwen-VL获取描述 → 汇总序列 → 与JSON步骤比对 → 若有错误，将错误信息+标准步骤送DeepSeek生成自然语言指导。

**DeepSeek始终作为大脑，只处理文字推理，视觉理解由“感官模型”承担并翻译成文字**，从而弥补DeepSeek纯文本的限制。

## 六、两种需求的实现流程详解

### 6.1 需求1️⃣：文字问答流程

```
学生输入问题：“七步洗手法第三步容易犯什么错误？”
        │
        ▼
1. 问题向量化 → 在Chroma中检索Top-3相关文本片段
        │
        ▼
2. 构建提示词：「你是一位临床带教老师。根据以下参考资料回答问题。
   参考资料：{检索到的JSON中的步骤、错误等内容}
   问题：{学生问题}」
        │
        ▼
3. 发送给DeepSeek生成答案
        │
        ▼
4. 返回答案；若JSON中有对应图片路径，前端自动渲染配图
```

### 6.2 需求2️⃣：模拟操作视频指导流程

```
学生上传换药操作视频（3分钟）
        │
        ▼
1. FFmpeg抽帧（每3秒）→ 60张图片
        │
        ▼
2. 每张图调用 Qwen-VL-Max ：「描述图中操作者动作、器械、操作对象」
   → 得到60条文本，如 ["揭除旧纱布", "用镊子夹碘伏棉球", "由外向内擦拭伤口"...]
        │
        ▼
3. 加载JSON中「伤口换药」的标准步骤：
   Step1: 揭除旧敷料
   Step2: 观察伤口
   Step3: 消毒伤口（由内向外画圈）
   Step4: 覆盖新敷料
        │
        ▼
4. 序列比对（动态时间规整或简单滑动窗口）：
   发现第3步描述多为“来回擦拭”而非“由内向外画圈”
        │
        ▼
5. 从JSON的common_errors中匹配：
   "消毒方向错误：未从伤口中心向外画圈，可能导致感染风险"
        │
        ▼
6. 将所有错误发现+正确步骤提交给DeepSeek，生成最终辅导评语：
   「在消毒环节，你采用了来回擦拭的手法。正确做法是……」
```

**实时性说明**：本版方案是“事后分析”，非“实时边做边指导”。但教师演示时，可提前将视频分段录制或让学生在每个步骤开始前说“下一步”，利用语音标记简化步骤分段（与教师展示逻辑一致）。

## 七、大一本科生的可行实施路径

### 7.1 技术学习清单（仅需以下基础）

- Python基础：变量、字典、列表、循环（1周）
- JSON基础：理解键值对嵌套（1天）
- 使用AI编程辅助：学习如何向DeepSeek描述需求获得代码（2天实践）
- FFmpeg命令行：只需掌握视频抽帧指令（1小时）

### 7.2 实施路线图（总耗时约4个月，每周课余10小时）

| 阶段 | 时间 | 任务 | 交付物 |
|------|------|------|--------|
| **准备** | 第1-2周 | 整理10个核心操作的步骤、器具、常见错误，写成标准JSON | `knowledge_base.json`（初版） |
| **一期** | 第3-6周 | 配置Chroma向量库，实现文字问答Demo | 命令行问答原型 |
| **二期** | 第7-11周 | 集成多模态模型，支持图片提问；实现视频抽帧与步骤比对 | 视频分析模块 |
| **三期** | 第12-15周 | 开发简易Web界面（可借用Gradio/Streamlit），整合两个功能 | 完整教学助手应用 |
| **收尾** | 第16周 | 测试、优化错误库、录制演示视频 | 项目报告 |

### 7.3 可用的低代码/零代码备选方案

如果Python学习曲线仍过高，可采用 **Coze（扣子）+ 外部知识库API** 的模式：
- 知识库仍用Chroma部署在后端（或直接用Coze自带表格知识库）
- 交互流程通过Coze的可视化工作流搭建
- 视频分析部分仍需少量Python（抽帧），但可将抽帧后的图片上传至Coze触发工作流

## 八、为什么这套方案适合医学生？

1. **知识贡献最大化**：医学生不需要研究AI算法，核心工作是把脑中默会的“哪步容易错”变成结构化的JSON错误库，这是带教经验的数字化，具有教研价值。
2. **复杂度阶梯式**：先用简单的文字问答快速看到成果（几周内），再逐步增加图片、视频功能，每一步都有正反馈。
3. **全AI辅助开发**：代码量约200行，且全部可由DeepSeek/ChatGPT生成骨架，学生只需做“自然语言调试”（告诉AI哪里报错、想要什么修改）。
4. **完全国产化**：DeepSeek + Qwen-VL + Chroma + Gradio/Streamlit，所有技术栈均免费或极低成本，且符合国内教育环境。

---

## 九、总结

本方案将医学教学的隐式经验显式化为**结构化知识库（JSON）**，利用**大模型路由**实现文字与多模态的协同推理，并通过**静态视频帧分析+步骤比对**替代复杂的实时动作识别，将技术实现门槛降至大一本科生可完成的水平。整个过程无需训练任何模型，仅通过调用国产大模型API和轻量开源工具即可实现全部功能，兼顾了教学改革的创新性与学生的可执行性。
