## 一、三种方案的定义

### 1. RAG数据库（语义向量库）

```
文档 → 切块 → Embedding模型转成向量 → 存入Chroma/Pinecone
查询 → 同样转成向量 → 用余弦相似度找最相关的文本块 → 喂给LLM
```

**本质**：让AI“理解意思”而非“匹配字词”。学生问“怎么暴露Calot三角”，即使知识库写的是“显露胆囊管与胆囊动脉汇合处”，两者语义相近，也能检索到。

### 2. Markdown数据库（结构化文档库）

```
文档 → 按层级手工整理成Markdown → 存在本地文件夹
查询 → 用关键词匹配或目录索引 → 返回整个文档或指定章节
```

**本质**：像一本电子书的目录+全文搜索（Ctrl+F），依靠**人工组织的结构**和**精确字词匹配**。

### 3. 混合数据库

```
文档 → 同时建立两套索引：
  ├── 向量索引（语义检索用）
  └── 结构化元数据索引（精确过滤用）
查询 → 先用元数据过滤范围 → 再在范围内做语义检索 → 喂给LLM
```

**本质**：取两者之长。比如先按“手术类型=腹腔镜胆囊切除”过滤，再在该手术范围内用语义检索找“Trocar放置位置”。

---

## 二、三种方案的核心对比

| 对比维度 | RAG数据库 | Markdown数据库 | 混合数据库 |
|---------|-----------|---------------|-----------|
| **检索方式** | 语义相似度 | 关键词/目录匹配 | 元数据过滤 + 语义检索 |
| **对同义表达的处理** | ⭐⭐⭐⭐⭐ 强 | ⭐ 弱（需精确匹配） | ⭐⭐⭐⭐⭐ 强 |
| **结果确定性** | ⭐⭐⭐ 有时飘移 | ⭐⭐⭐⭐⭐ 确定性强 | ⭐⭐⭐⭐ 较好 |
| **维护成本** | 中等（自动向量化） | 高（手工整理结构） | 较高（维护两套系统） |
| **开发复杂度** | 中等（需Embedding） | 低（纯文本） | 高（需同时掌握两者） |
| **适合的数据类型** | 大量非结构化文本 | 高度结构化的步骤/规范 | 既有非结构化文本又有结构化数据 |
| **成本** | 需Embedding API调用 | 零成本 | 需Embedding API调用 |

## 三、针对本项目的适配度分析

### 项目的真实需求拆解

| 目标 | 输入 | 输出的本质 | 对知识库的要求 |
|------|------|-----------|--------------|
| **目标1：文字问答** | 任意自然语言问题（如“腹腔镜手术中如何避免胆管损伤？”） | 基于知识库生成专业回答 | **语义检索**——学生表达方式多样，需要理解问题意图 |
| **目标2：实时视频指导** | 当前操作描述（如“学生正在用持针器夹持缝合针”） | 判断属于哪个步骤、是否正确、如何纠正 | **精确步骤匹配**——需要一份结构化的“标准答案卡”做比对 |

### 关键发现：两个目标需要的是**不同形态**的知识

- **目标1**需要的是一个"可以被自由检索的知识库"——适合用向量检索
- **目标2**需要的是一份"结构化的标准操作步骤清单"——适合用精确的JSON结构，根本不需"检索"，而是直接加载到内存中作为Agent的比对基准

> 换句话说，这两个目标对数据库的需求**并不完全重叠**。

---

## 四、分场景适配度打分

### 目标1：文字问答助手

| 方案 | 适配度 | 原因 |
|------|-------|------|
| RAG数据库 | ⭐⭐⭐⭐⭐ | 语义检索能理解各种提问方式，学生用口语化表达也能找到正确答案 |
| Markdown数据库 | ⭐⭐ | 学生必须用与文档一致的关键词才能搜到，容错性差 |
| 混合数据库 | ⭐⭐⭐⭐ | 效果更好但复杂度过高，对目标1来说"杀鸡用牛刀" |

### 目标2：实时视频指导

| 方案 | 适配度 | 原因 |
|------|-------|------|
| RAG数据库 | ⭐⭐ | 向量检索可能匹配到语义相近但步骤不对的内容，缺乏精确性 |
| Markdown/JSON结构化 | ⭐⭐⭐⭐⭐ | 把每个步骤的关键动作、常见错误写成JSON，Agent直接逐条比对，不依赖检索 |
| 混合数据库 | ⭐⭐⭐ | 可以做到，但目标2根本不需要"检索"，需要的是"比对" |

## 五、最终推荐：轻量级双轨方案

### 核心思路：用同一份"源文件"，衍生出两种"使用形态"

```
                ┌─────────────────────────┐
                │  源知识库（JSON文件）     │
                │  人手维护，结构化存储    │
                │  包含：步骤、动作、错误   │
                └──────────┬──────────────┘
                           │
            ┌──────────────┴──────────────┐
            │                             │
            ▼                             ▼
   ┌──────────────────┐        ┌──────────────────┐
   │ 向量化版本        │        │ 结构化步骤清单    │
   │ （自动从JSON生成）│        │ （直接加载JSON）   │
   │ 存入Chroma       │        │ 供Agent逐条比对    │
   │ 供目标1语义检索  │        │ 供目标2步骤匹配    │
   └──────────────────┘        └──────────────────┘
```

### 具体做法（分三步）

**第一步：建立统一的源知识库（一个JSON文件搞定）**

```json
{
  "手术名称": "腹腔镜胆囊切除术",
  "步骤": [
    {
      "步骤编号": 1,
      "步骤名称": "建立气腹与Trocar放置",
      "关键动作": "脐下缘切开1cm，Veress针穿刺建立气腹，压力维持12-15mmHg",
      "详细描述": "患者取头高足低位，术者立于患者左侧。脐下缘做1cm弧形切口...",
      "常见错误": ["气腹压力不足", "Trocar穿刺角度过大致腹腔脏器损伤"],
      "参考图": "step1.png"
    },
    {
      "步骤编号": 2,
      "步骤名称": "暴露Calot三角",
      "关键动作": "向下牵引十二指肠，向上提起胆囊底，显露肝十二指肠韧带",
      "详细描述": "用抓钳夹持胆囊底部向上提起...",
      "常见错误": ["牵引方向不当致胆总管损伤", "未充分暴露即开始分离"],
      "参考图": "step2.png"
    }
  ]
}
```

**第二步：为两个目标分别生成"使用形态"**

| 目标 | 生成方式 | 使用的工具 |
|------|---------|-----------|
| **目标1（问答）** | 把JSON中每个步骤的"详细描述"字段提取出来，转成纯文本，切片后用Embedding API向量化，存入Chroma | 智谱Embedding API + Chroma |
| **目标2（视频指导）** | 直接把整个JSON文件加载到Python内存中，Agent用`for`循环逐条比对当前操作描述与每个步骤的"关键动作" | 不需要数据库，一个变量即可 |

**第三步：实际调用逻辑**

```python
# 目标1：用户文字问答
question = "胆囊切除术中如何避免损伤胆总管？"
related_chunks = chroma_collection.query(question)  # 语义检索
answer = deepseek.chat(question, context=related_chunks)

# 目标2：实时视频指导（不需要检索数据库！）
current_action = glmv.describe(frame)  # 多模态模型分析当前画面
for step in json_data["步骤"]:
    prompt = f"判断'{current_action}'是否属于步骤'{step['关键动作']}'？"
    match = deepseek.judge(prompt)
    if match == "是":
        # 比对常见错误，给出纠正建议
        feedback = deepseek.evaluate(current_action, step["常见错误"])
        if feedback.has_error:
            tts.speak(feedback.correction)
        break
```

## 六、一句话总结

> **不选RAG，不选Markdown，选"JSON源库双轨制"**——用一份人手维护的结构化JSON作为唯一真相来源，自动衍生出向量索引（喂给目标1做语义问答）和步骤清单（喂给目标2做精确比对）。这是**最简单、最可控、最适合大一学生**的方案，既不需要维护复杂的混合数据库，也不会因纯向量检索导致步骤匹配不精确。

## 七、关键认知：目标2根本不需要"数据库"

学生在做实时视频指导时，Agent面对的是一个**步骤固定的操作流程**。它要做的是：

1. 从摄像头画面中识别出学生正在做第几步
2. 将该步骤的标准动作和学生当前动作做比对
3. 判断是否有偏差

这个过程中，"知识库"的角色更接近**"考试标准答案"**——一共就5-10个步骤，直接加载到内存里逐条比对即可，完全不需要向量检索。只有目标1（自由问答）才需要真正意义上的检索式数据库。
