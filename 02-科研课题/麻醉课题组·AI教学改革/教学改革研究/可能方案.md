## 总体方案概览

| 目标 | 核心功能 | 输入 | 输出 | 主要技术 |
|------|---------|------|------|---------|
| **目标1：文本问答助手** | 学生用文字提问标准操作流程，系统基于知识库回答 | 文字问题（如“腹腔镜胆囊切除的Trocar位置”） | 文字+图片/示意图 | RAG + 国产大模型（DeepSeek） + 向量数据库 |
| **目标2：实时视频指导** | 摄像头捕获学生模拟操作，实时分析动作并纠正 | 教室摄像头视频流 | 屏幕文字提示 + 语音纠正 | 多模态大模型（GLM-4V-Flash） + Agent比对引擎 + TTS |

**架构核心**：两个目标共享一个**经过结构化处理的操作知识库**，知识库内包含标准步骤、关键动作描述、常见错误、参考图片等。

---

## 目标1：文字问答助手（临床操作流程查询）

### 1. 怎么做（分三步）

**第一步：知识库构建**
- 将各种格式的教学资料（文本指南、DICOM、手术视频、图片）全部**转化为统一的结构化文本**。
- 整理成每个操作步骤的标准化描述（JSON/Markdown），包含步骤名称、关键动作、器械、常见错误等。

**第二步：向量化与存储**
- 使用开源向量数据库（如Chroma）将文本转为向量并存储。

**第三步：部署问答Agent**
- 用户提问 → 检索相关步骤文本 → 拼接提示词发送给大模型 → 生成回答。

### 2. 技术栈与用法

| 技术/工具 | 用途 | 具体怎么用 |
|----------|------|-----------|
| **pydicom + SimpleITK** | DICOM文件解析 | 读取DICOM文件元数据（患者信息、层厚等），导出关键帧为JPEG，形成文字描述。 |
| **智谱GLM-4V-Flash** | 多模态理解（图像/视频抽帧转文字） | 将DICOM关键帧、手术视频抽帧、病理图片等通过API发送，要求模型“描述图像中的医学发现和操作”。免费额度够用。 |
| **百度AI视频分析/图片理解** | 视频分析备选方案 | 用于自动抽取视频关键帧并打标签，辅助生成步骤文本。 |
| **Chroma** | 本地向量数据库 | 将上一步得到的文本切片后存入Chroma，方便后续检索。 |
| **LlamaIndex** | RAG框架 | 用SimpleDirectoryReader加载文本，构建索引，定义查询引擎。学生只需几行代码即可实现问答。 |
| **DeepSeek V4 Pro** | 最终回答的推理LLM | 接收检索到的上下文和用户问题，生成专业、准确的医学回答。API价格极低，新用户有大量免费额度。 |

### 3. 工作流程示意

```
用户提问：“胆囊切除术中如何暴露Calot三角？”
      ↓
LlamaIndex检索向量库 → 得到相关步骤文本
      ↓
Prompt = 上下文 + 用户问题 → 发送至DeepSeek
      ↓
回答：“首先需向下牵引十二指肠以显露肝十二指肠韧带，然后……”
```

## 目标2：实时视频监督（学生模拟操作纠正）

### 1. 怎么做（分四步）

**第一步：知识库结构化**
- 与目标1共享知识库，但需要额外整理成**严密的结构化步骤清单**（如JSON），包含每个步骤的判断标准和常见错误。

**第二步：实时视频帧捕获**
- 用Python的OpenCV库连接教室摄像头，每秒截取1帧。

**第三步：帧内容理解（多模态模型）**
- 将截取的帧实时发送给国产多模态大模型，要求它描述“当前学生正在做什么操作，器械位置如何”。

**第四步：智能比对与纠正**
- 将模型对当前操作的描述，与知识库标准步骤进行比对。
- 使用DeepSeek作为Agent判断：当前操作是否匹配、是否正确、错误原因及纠正建议。
- 如果发现错误，调用TTS（科大讯飞）进行语音播报，并在屏幕显示纠正文字。

### 2. 技术栈与用法

| 技术/工具 | 用途 | 具体怎么用 |
|----------|------|-----------|
| **OpenCV** | 摄像头视频流捕获 | 读取教室摄像头（`cv2.VideoCapture`），每1秒保存一帧为JPEG格式。完全免费。 |
| **智谱GLM-4V-Flash** | 实时帧操作描述 | 将捕获的帧转为base64，通过API发送，配合提示词“请详细描述医学生当前正在进行的操作，指出他使用的器械和动作”。 |
| **Chroma + 结构化步骤库** | 存储标准操作步骤 | 每个步骤的JSON存入Chroma，便于检索当前应该处于哪个步骤。 |
| **DeepSeek V4 Pro** | Agent推理比对引擎 | 接收“当前操作描述”+“标准步骤描述”，判断是否匹配，并生成纠正建议。提示词示例：“当前学生操作描述为……，标准步骤要求……，请判断操作是否正确，若错误请给出具体纠正方法。” |
| **科大讯飞在线TTS** | 语音合成输出 | 将纠正文本转为自然语音，通过教室音箱播放。免费额度每日500次。 |

### 3. 模型路由策略（核心逻辑）

为保证系统可靠性和成本控制，采用**简单路由**：
- **所有图像/视频帧理解** → 固定在**GLM-4V-Flash**（性价比最高的国产多模态模型）。
- **所有文本推理/比对** → 固定在**DeepSeek V4 Pro**（长上下文推理能力强）。
- 不涉及复杂模型切换，仅根据输入类型调用对应API。大一学生无需掌握模型路由框架，用`if-else`判断即可。

### 4. 工作流程示意

```
摄像头画面 → 每秒取一帧（OpenCV）
      ↓
发送至GLM-4V-Flash → 返回当前操作描述
      ↓
查询Chroma → 获取当前应该进行的标准步骤
      ↓
描述 + 标准步骤 → 发送至DeepSeek判断
      ↓
如果错误 → 科大讯飞TTS语音提醒 + 屏幕显示纠正文字
```

## 统一说明：多模态模型的具体分工

| 模型名称 | 专长 | 在目标1中的角色 | 在目标2中的角色 |
|---------|------|---------------|---------------|
| **智谱GLM-4V-Flash** | 视觉理解（图像、视频帧） | 把DICOM/视频/图片“翻译”成文字 | 实时理解学生操作画面 |
| **DeepSeek V4 Pro** | 文本推理、长上下文、中文对话 | 根据检索内容回答用户问题 | 判断操作是否符合标准并给出纠正 |
| **科大讯飞TTS** | 语音合成 | 不涉及 | 将纠正建议朗读出来 |

**注**：所有API均在国内可直接调用，无需翻墙，且均提供可观的免费额度，完全满足学生开发测试需求。

## 实施建议（给大一医学生）

- **目标1先行**：先花2周搭好文本问答系统，熟悉RAG和API调用。
- **目标2渐进**：在目标1的基础上，增加视频流模块，限定一个极简场景（如洗手、缝合打结）做演示。
- **开发环境**：Anaconda + Jupyter Notebook，所有代码一个`.py`文件即可跑通。
- **数据安全**：使用脱敏教学数据集，摄像头不录制真实患者，仅在模拟训练室部署。

此方案代码量少，依赖的均为现成API，既保证技术可行性，又能让学生深刻理解“AI在医学教育中如何落地”。
